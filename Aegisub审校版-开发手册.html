00 · OVERVIEW

项目概况

维护者是一位中文字幕组审校编辑，不直接编写 C++：功能以中文工作流需求描述提出，由 AI 辅助编码完成后在实际审校流程中验收。接手协作时请把这一点作为默认工作模式——需求侧关心的是"我在校对时怎样少按几次键"，实现侧的取舍在本文档各功能的"坑"小节里都有记录。

全部定制集中在 master 分支工作区，基线提交 ce97a367c（"Cross-build Intel macOS jobs on Apple Silicon (#705)"）。改动分三类：

  • 对上游文件的修改（52 个）：以 src/ 下的播放、视频、网格、对话框为主，附 libaegisub/windows/path_win.cpp 一个关键 bug 修复。
  • 新增 C++ 模块：样式特效 ass_style_fx、自动对帧工具 visual_tool_timing_region、字幕格式审查 subtitle_format_audit、AI 内嵌翻译 ai_assistant + command/ai.cpp。
  • 周边文件：6 个 Automation Lua 脚本、PO 编译工具 tools/compile_po.py、构建辅助脚本（build-local/，不入库）、启动命令 打开本地新版Aegisub.cmd。

验证以 Windows x64 本地构建为准：产出 build-local\aegisub.exe，再由 link-ready.cmd 链接成日常使用的 aegisub-ready.exe。macOS 路径未做针对性改动（除 aegisublocale.cpp 保持原逻辑）。

安全红线

阿里云百炼 API 密钥永远不写入仓库：运行时保存在用户 %APPDATA% 的 Aegisub 设置（Tool/AI/API Key），首次运行从旧 Lua 版配置 %APPDATA%\ai_translate.conf 自动继承。曾有密钥在聊天中暴露，必须先在百炼控制台轮换。文档、提交信息、日志里都不允许出现密钥本体。

01 · BUILD

构建与运行（Windows）

工具链与环境

  • Visual Studio 2022 Build Tools（MSVC，x64），路径以 VsDevCmd.bat 为准。
  • Python + meson + ninja（构建调用一律走 python -m ninja，不依赖全局 ninja）。
  • Git for Windows：LuaJIT 子项目 configure 需要 sed。PowerShell 里调脚本时必须先补 PATH：
$env:PATH = 'C:\Program Files\Git\usr\bin;' + $env:PATH
cmd /c 'build-local\rebuild.cmd > build-local\my_build.log 2>&1'

子项目（wxWidgets 3.2.12、FFmpeg、dav1d、curl、boost 1.83、hunspell 等）全部走 meson subproject fallback，已在 build-local 内配置完毕，日常增量构建不需要重新 setup。

两个脚本的分工

脚本内容产物
build-local\rebuild.cmdVsDevCmd → python -m ninja aegisub.exebuild-local\aegisub.exe（完整重链接产物）
build-local\link-ready.cmdVsDevCmd → link @aegisub-ready.exe.rspbuild-local\aegisub-ready.exe（日常使用的 "ready" 版）
打开本地新版Aegisub.cmd（仓库根）启动 %~dp0build-local\aegisub-ready.exe，缺失时提示路径并暂停—（纯 ASCII 内容 + 中文文件名由桌面快捷方式调用，避开编码问题）

aegisub-ready.exe.rsp：手工维护的链接清单

这是本项目最容易踩的坑。aegisub-ready.exe 不走 ninja 链接，而是拿 aegisub.exe.p/ 目录下已编译好的 .obj 手工链接。清单是仓库外文件（build-local 被 .gitignore 的 build*/ 规则忽略）。

  • obj 命名规则：aegisub.exe.p/src_<路径，/→_>.cpp.obj，如 src_command_ai.cpp.obj、src_ai_assistant.cpp.obj。
  • 新增/删除源文件时，必须同步增删 rsp 里对应 obj 行（按字母序插到正确位置），否则 ready 版会缺符号（LNK2019）或多出陈旧 obj。
  • 只改已有文件内容时不需要动 rsp，重链即可。

构建纪律（血泪经验，务必遵守）

RULE
  • 改动任何头文件后一律全量构建（跑完整 ninja，不挑目标文件增量编译），避免不同 TU 之间的 ODR 不一致造成"编译能过、运行崩溃"。
  • 绝不把实时构建输出接管道过滤（会吞掉失败信号）。正确做法：整段重定向到日志文件，结束后再 grep FAILED|error C|LNK。
  • 整文件重写后，链接前先 grep 确认头文件声明的每个符号在源文件里都有定义体（曾发生 AIChatComplete 函数体被重写弄丢，4000+ 目标文件白编译才在链接期暴露）。
  • exe 被占用时先问维护者，绝不直接杀进程。约定流程：请求关闭实例 → 等待回复"已关闭" → 再链接。维护者常在另一台实例里挂着未保存的字幕。

本地化的编译进链

顶层 meson.build 新增 custom_target('zh_CN-catalog')：用 tools/compile_po.py（纯 Python PO→MO，替代 Windows 缺失的 msgfmt）把 po/zh_CN.po 编成 aegisub-zh_CN.mo，build_by_default 且加入 exe 的 link_depends，并复制到 po/zh_CN/LC_MESSAGES/aegisub.mo 供 wxWidgets 按标准布局查找。po/meson.build 本身没有内容改动。

相关：README 新增 macOS 的"带 FFmpeg 家族编解码"构建段（AV1 靠内嵌 dav1d、VP9 靠内嵌 FFmpeg，纯解码侧），配套 subprojects/checkasm.wrap 是 wrap-redirect 存根，指向 dav1d 内的 checkasm 依赖，让子项目回退的 FFmpeg 构建不再报缺 wrap。

开发规范与约定

约定做法原因
UI 全简体中文新字符串 STR_MENU("区域截图翻译")、消息框等直接用中文 msgid / 硬编码中文 + to_wx()未翻译时 gettext 原样返回 msgid，即显示中文；避免每次都改 po 造成大 diff。集中翻译由 po/zh_CN.po 批量补录

撤销体系改文本 COMMIT_DIAG_TEXT、改时间 COMMIT_DIAG_TIME、改样式 COMMIT_STYLES、排序 COMMIT_ORDER；批量操作只 Commit 一次审校工作流依赖一次 Ctrl+Z 回到改动前；一次批量一个撤销点
后台线程网络/解码走 agi::dispatch::Background().Async，结果回投 Main().Async；用 shared_ptr<atomic<bool>> 的 alive/cancel 双标志防护模态框销毁后迟到的回调必须无害；取消通过 curl 进度回调实现
无成功弹窗操作成功用状态文字/日志窗口反馈；仅错误与危险操作用对话框维护者明确要求，高频操作弹窗是灾难

03 · FEATURES

功能改动详解（F01–F10）

F01

倍速播放（变速不变调）

动机

审校听译时需要 2×/4× 快速过一遍音轨，同时保持音调可辨。原 Aegisub 完全没有变速能力。

交互：视频工具栏播放键后内嵌一个 wxChoice 下拉（0.5x / 1x / 2x / 4x），初始档位从存储速度换算；tooltip 注明"声音跟随，其他速率保持音调"。

视频时钟：VideoController 的 10ms 定时器改为虚拟时间轴 virtual_ms = start_ms + elapsed * play_speed；SetSpeed() 在当前显示帧重新锚定时钟（start_ms = TimeAtFrame(frame_n) 加重置起点），播放中变速不跳画面，并把持久化写进 Tool/Playback/Play Speed（百分数，钳 25–400）。

音频链路：AudioPlayer 基类新增虚函数 SetSpeed(double)，默认实现返回 speed==1.0 ? 1.0 : 0.0——0 表示"不支持"，调用方策略是宁可不发音，也不让声画漂移（Play()/PlayLine()/SetSpeed() 收到 ≤0 就 Stop 音频而不是继续旧速度）。

DirectSound2 播放器的真实现（本功能核心，+379 行）：首选内建 TimeStretchEngine——流式 WSOLA 时距伸缩，直接从 agi::AudioProvider 读样本：hop≈20ms、Hann 窗 50% 重叠、在 ±search 范围用 SSD 搜最佳拼接点再 overlap-add 合成，变速同时保持音调；支持 int16/int32/float。设备缓冲加 DSBCAPS_CTRLFREQUENCY 作为后备路径（频率整体平移，会变调，超出 DSBFREQUENCY 范围时拒绝并返回 0）。线程与 UI 用 Win32 event + pending_speed 握手重启播放。伸缩模式下播放位置按输入游标（stretcher.Cursor()）折算回时间轴。

新建播放器时（切换音频设备/文件），AudioController::OnAudioPlayerChanged 立即把存储倍速套到新播放器上。

涉及文件角色
src/audio_player_dsound2.cppTimeStretchEngine + 线程变速握手
src/video_controller.{h,cpp}虚拟时钟、SetSpeed、持久化
src/audio_controller.{h,cpp}、src/include/aegisub/audio_player.h能力协商接口
src/toolbar.cppwxChoice 控件与档位映射
坑
  • 非 DirectSound2 播放器（如 DSOUND 旧实现）不支持变速——表现是倍速下静音而非变调，这是刻意设计。
  • Populate() 会销毁工具栏控件，speed_choice 指针必须置空再重建，否则悬垂。
F02

字幕审校模式（Review Mode）

动机

逐行审校节奏：播当前行（前后各留 1 秒）、进编辑框自动暂停、改完可选择自动重播、表格里高亮"正在播的行"和"时间重叠的行"。原 Aegisub 一切换选中行就打断播放。

命令与入口：review/mode（开关，视频工具栏按钮）、review/play_pause（继续/暂停且不动当前行）、review/preview（预览当前字幕）。快捷键迁移：默认把 Ctrl-P 从 video/play 换成 review/play_pause、Ctrl-Shift-P 绑定预览（一次性迁移 "review playback controls"，已自定义 Ctrl-P 的用户不动）。

VideoController 新增状态机：review_mode / review_preview / review_was_playing / review_saved_frame / focus_paused / review_edit_time，信号 ReviewModeChange 供 base_grid、subs_edit_box、video_box 订阅。OnActiveLineChanged 在审校模式下跳过 Stop+JumpToTime（这是"切换选中不打断播放"的实现点）。Stop() 在预览中会转为取消预览。

预览一条字幕：PlayReviewPreview(start,end,AssFile*) 把当前内存字幕文件（含未保存修改）塞进视频 provider，播 [start−1s, end+1s]，结束或取消时 FinishReviewPreview() 恢复 provider 的常规字幕源并跳回原帧。可重入（预览中再预览不丢初始状态）。

焦点联动：编辑框侧 subs_edit_box 用 120ms wxTimer 轮询 wxWindow::FindFocus() 上溯父链判断焦点是否在编辑区/音频盒（注释说明：Scintilla 原生控件会吞 SET/KILL_FOCUS，只能轮询），焦点入→视频自动暂停，焦点出→从暂停帧续播；若期间该行内容被提交过（review_edit_time 有值）且开了"改后重播"，先 seek 到该时间再播。

视频盒三个审校专属按钮（video_box.cpp，默认隐藏）：预览±1秒（跑 PlayReviewPreview）、重叠高亮开/关、改后重播开/关；进入审校模式还会把 video/opt/autoscroll 工具栏按钮隐藏（依赖 F10 的 toolbar::SetCommandVisible）。

网格高亮（base_grid）：正在播放的行琥珀底 255,222,150 + 2px 描边 230,135,20；重叠行粉底 255,218,222；开启重叠高亮时活动行及其碰撞行加 232,133,140。重叠映射 UpdateOverlapRows() 按起止时间扫描线标记，时间编辑提交（COMMIT_DIAG_TIME）后即时刷新。优先级：选中 > 播放行 > 注释行。

坑
  • 高亮颜色硬编码在 UpdateStyle，不走设置项——后续如需主题化从这里入手。
  • PlaybackChange 信号已定义并多处触发，但目前全树无消费者，属预留接口。
  • frame_main 析构新增 videoController->Stop()：退出时先让审校预览恢复常规字幕源，否则 provider 与观察者析构顺序会崩（F10 关联）。
F03

自动对帧（Frame Match：拖框 + 匹配 + 批量提速）

动机

烧录字幕（硬字幕）视频里，把字幕行的起止时间对齐到画面上字幕实际出现/消失的帧。人工逐帧找太慢，改为：在视频上拖一个紧贴字幕文本的框 → 对当前行自动找出现区间；选中多行可批量。

入口：视频工具 video/tool/frame_match（工具栏按钮 + 菜单"对帧助手"，二次按下退回十字工具），批量命令 video/tool/frame_match_batch（需视频 provider + 非空网格选区，走静态 VisualToolTimingRegion::BatchMatchSelection()）。参考帧 = 当前显示帧，用户要先停在字幕可见的帧再拖框。

匹配算法（visual_tool_timing_region.cpp，核心 MatchLineToRegion()）：

  • 区域按脚本分辨率→归一化坐标→采样为 ≤320×128 的网格（GetEffectiveLayoutResolution 处理脚本/视频分辨率差异；frame->flipped 已处理）。
  • 双极性二值掩码：亮字（luma≥215 或 RGBmax≥180 且 chroma≥90）与暗字（luma≤60），兼容白字和黑描边字。
  • 相似度用 Dice：同位置 200·|交| / (|参考|+|当前|)。
  • 抗干扰：±6 秒按约 1 秒取样做"持久性扫描"，点亮率 ≥85% 的格子判为台标/横幅等静态元素剔除；参考帧图案至少 12 个有效格才开跑。
  • 粗搜 ±10 秒、步长约 0.5 秒，命中后对出现/消失边界逐帧前进细修（所有扫描均为前进单程，配合软解关键帧 seek 的特性调优）。

批量提速机制（此前需求单上的"顺序预取提速""批量接缝链接"就落在这里，不在 async provider——视频解码器本身有缓存）：

  • 按时间排序处理；跨行共享 MaskCache（≤384 帧 LRU），后续行直接搭已解码帧的前程。
  • 链式提示：上一行结束与新行预期开始相差 ±1.5 秒内时，只探接缝附近 3 帧，≥3 次命中才收窄窗口（错链代价大，宁可回退宽搜）。
  • 冲突消解两轮：移动后互相重叠的行，以 min(95, 基准相似度 + 轮次×重跑步长) 重配准，邻行 ±80ms 边界钳制；结果退化的行回滚原时间。
  • 提交一次 "batch match subtitle timings"（COMMIT_DIAG_TIME），可撤销；进度框可中止（status 枚举含 Cancelled）。

阈值设置 UI：视频属性对话框新增 Frame Match Assistant 分栏：最小相似度 %（25–95，默认 70）、重跑步长 %（5–30，默认 15），点确定才落 OPT。

区域持久化：四个 double 选项 Tool/Frame Match/Region X0/Y0/X1/Y1（−1 = 未框选），Esc/右键只清当前橡皮筋不清已保存区域。AI 截图翻译直接复用这个区域（F08），这是当初"复用自动对帧交互"决策的落点。

坑
  • 批量模式内层 try_match 异常被静默吞掉继续下一行——排障时先看进度文本再看日志。
  • 单行匹配的进度总量是硬编码估计（66 样本），不是精确值。
  • 键盘事件钩子：工具消费按键依赖新加的 VisualToolBase::OnKeyDown 虚函数（F10），帧匹配期间按 Esc 取消由这条链驱动。
F04

样式特效：多层描边 / 外发光 / 淡入淡出（Style FX）

动机

字幕组的标题字常需要 2–32 层渐宽描边、外发光、整行淡变。ASS 样式只支持单层 \3c/\4c/\bord/\shad。方案：把这些做成 Aegisub 私有样式扩展，编辑时内部模拟渲染，保存/导出时"展开"成普通 ASS 也能播的堆叠事件。

数据模型（ass_style.h/cpp）：AssStyle 新增 strokes（vector：width/blur/color）、glow_enabled/glow_width/glow_blur/glow_color、fade_in_ms/fade_out_ms；序列化 GetFxData/SetFxData 为带版本号 CSV（当前 v3：全局发光 + 淡变 + n 层描边；兼容读 v1 单层/v2 渐变弃用；字段数严格校验，坏数据静默忽略）；HasStyleFx() 判任一特效存在。

编辑 UI（dialog_style_editor）：右侧新增 "Layer Styles" 分组：描边行动态增删（各层颜色/宽/模糊，上限 32）、外发光开关与颜色/宽/模糊、淡入/淡出 ms（0–10000）。预览即时刷新（spin-double 事件显式绑定取代了原 OnChildFocus 方案）。

展开/折叠（ass_style_fx.h/cpp，核心新模块）：

  • ExpandStyleEffects(AssFile&, bool markers)：每个 FX 行复制成"最宽描边在底 … 正文在最上"的事件栈；自动生成样式命名 __AegisubFx_<id>_<base|glow|strokeN>；描边层用 {\1a&HFF&\2a&HFF&\4a&HFF&} 遮填充只留描边，模糊转 {\blur}，淡变转 {\fad}；各层按对齐方式计算 {\pos} 钉死位置（文本已有 \pos/\move 则整体跳过）。markers=true 时每层前插一条 Comment "AegisubFxGroupV1:n:…" 记录原行。
  • CollapseStyleEffects(AssFile&)：加载时识别标记注释，把事件栈收回为原始单行并删除生成样式；坏标记原样保留。收回发生在 subtitle_format_ass.cpp 的 ReadFile。
  • 渲染路径（预览/视频）以 markers=false 展开：subs_preview、async_video_provider（ProcFrame 两个分支 + GetSubtitles，均为复制 AssFile 后展开）。保存/导出以 markers=true 展开，因此外部播放器看到的是等价但行数更多的普通 ASS。

持久化：.ass 文件把特效写进 Script Info 条目 Aegisub Style FX = <编码样式名>,<fxdata>；样式存储文件（AssStyleStorage）在每个样式后插一行 ;AegisubStyleFX:<encoded>。两者对外部 ASS 解析器都是可忽略注释/键。

坑
  • 展开会改变事件数与 layer 值（组内重排，组外不动）——diff/审校比对时注意。
  • async_video_provider 每次（重）载字幕都做整 AssFile 深拷贝展开，大文件 + 频繁切换字幕源时有性能成本；逐帧脏标记路径未变。
  • 注释行与无特效行完全透传。

F08

AI 内嵌翻译（阿里百炼 DashScope）

动机

旧 Lua 原型（AI辅助翻译.lua）经外部进程调 ffmpeg，链路长且脆。经评估改为原生内嵌（维护者拍板"直接开工内嵌版"）：截图走内存帧缓冲，音频走 AudioProvider 切片，网络走已在构建内的 libcurl。Lua 版保留对照至稳定后删除。

入口：字幕菜单两项（自动置灰逻辑：截图翻译需视频 provider；音频翻译需音频 provider + 非空选区），命令在 command/ai.cpp，全部实现在 ai_assistant.cpp（约 915 行，含对话框与 curl 层）。

接口约定：OpenAI 兼容 POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions。视觉消息 = image_url(data:image/png;base64,…) + text；音频消息 = input_audio(data:;base64,WAV, format wav) + text；模型名含 "omni" 必须 stream:true，按 SSE data: … 行拼接 choices.0.delta.content 直到 [DONE]。提示词与 Lua 版逐字一致（原文=… 译文=… 格式 + 同套 extract_translation 提取兜底，保证两版输出可对照）。

功能 1 区域截图：主线程抓当前帧（AsyncVideoProvider::GetFrame(frame, time, raw) → wxImage），按百分比裁剪（默认读 F03 的 Frame Match 区域，面板区域四项可改）、>1280 宽则缩放、PNG 编码 → base64 → 后台线程请求。结果"原文/译文"两个可编辑框，"写入当前行"→ line->Text = …（换行转 \N）→ COMMIT_DIAG_TEXT。

功能 2 音频翻译：每条选中行按 [start−PadStart, end+PadEnd] 从 agi::AudioProvider 取样本，内存里降混单声道 + 线性重采样 16k + 拼 WAV 头（不依赖 ffmpeg；provider 本身带锁线程安全），逐条串行请求，进度"第 d/N 条完成"，汇总可编辑框；"写入选中行"按【第N条 h:m:s】块解析回填。

线程与生命周期：模态框（ShowModal）保证请求期间项目/视频/音频对象不会变化；alive_/cancel_ 为 shared_ptr<atomic<bool>>，后台结果回投主线程前一律查 !*alive 直接丢弃；取消按钮置 cancel，curl 的 XFERINFOFUNCTION 轮询它；运行中点关闭会被 veto（提示"正在取消后台任务，请稍候…"），"强制关闭"按钮直接 EndModal；析构兜底置位双标志。

配置与密钥：Tool/AI/* 12 个键（见第 05 章）。密钥输入框 wxTE_PASSWORD 打码；密钥为空时自动读 %APPDATA%\ai_translate.conf 的 api_key= 行继承 Lua 版配置。区域/模型/语言改动即时写回 OPT。

错误话术（全部中文、面向操作者）：401→"API 密钥无效…"；403→"模型未开通：…请到百炼控制台「模型广场」开通该模型后重试"；429→频率/额度；网络失败→"请检查网络或代理"；SSE 空内容/JSON 异常附原始响应前 300 字符。

坑
  • libcurl 依赖挂靠在 enable_update_checker 之下（WITH_UPDATE_CHECKER 宏 + curl 进全局 deps）。本构建开启；若关掉的配置编 AI 功能，代码用 #ifndef 分支给中文提示"此版本编译时未启用网络支持"。
  • 抓帧刻意留在主线程（一次取一帧，短阻塞），避免与视频显示的 provider 竞态；只有网络与 WAV 组装进后台。
  • rsp 清单已含 src_ai_assistant.cpp.obj 与 src_command_ai.cpp.obj——新增 AI 相关源文件时记得同步。
F09
